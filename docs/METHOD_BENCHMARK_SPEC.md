# Differential-abundance benchmark specification v1.0

Date frozen: 2026-10-25

## Scope

Compare differential-abundance methods on the five frozen effect scenarios
generated by `p4_run_effect_interface.py`.

The benchmark asks whether a method recovers the pre-specified target features
while controlling the false-discovery proportion under project-blocked
case-control assignment.

## Analysis unit and model

- Experimental unit: project.
- Conditions are assigned within project.
- Any method that supports random effects must include project.
- Fixed-effect-only methods are retained as diagnostic baselines but cannot be
  interpreted as respecting the blocked design.
- The `unassigned` catch-all is excluded from differential-abundance testing.

## Multiple-testing family

- Family: all tested features within one method × scenario × simulation
  replicate.
- Primary adjustment: Benjamini-Hochberg at FDR 0.05.
- Sensitivity adjustment: Benjamini-Yekutieli at FDR 0.05.
- Do not select the family or adjustment after inspecting results.
- Pre-filtering, if used, must be based on an independent mean-abundance rule
  fixed before testing. Variance or preliminary-test filtering is forbidden.

## Frozen scenarios

- `no_effect`
- `sparse20_fc1_19`
- `sparse20_fc1_41`
- `sparse20_fc2`
- `dense200_fc1_41`

Twenty simulation seeds per scenario will be run after method runners pass
smoke tests.

## Method grid

| Method | Role | Project handling | Primary setting |
|---|---|---|---|
| ALDEx2 | Compositional Monte Carlo | paired/project-blocked contrast | Welch t, 128 Monte Carlo instances |
| ANCOM-BC2 | Compositional log-linear model | project random effect | BH q < 0.05 |
| LinDA | Linear model after CLR | project fixed or mixed sensitivity | BH FDR 0.05 |
| MaAsLin | Multivariable linear model | project random effect | BH FDR 0.05 |
| CLR mixed model | Transparent baseline | project random intercept | Wald/BH FDR 0.05 |
| CLR Wilcoxon | Diagnostic baseline | project-stratified sign/rank where possible | BH FDR 0.05 |

Method versions, exact function calls and package versions must be written to the
run manifest.

## Truth definitions

- Biological target: `is_target = TRUE` in `full_feature_truth.csv`.
- True positive: target feature rejected at FDR 0.05.
- False positive: non-target feature rejected.
- `unassigned` is excluded from both target and tested sets.

Compositional closure effects on non-target features are retained in the truth
file but do not convert those features into biological targets.

## Primary endpoints

1. **FDP control**: realized false-discovery proportion across replicates.
2. **Power**: mean proportion of target features rejected.
3. **F1**: harmonic mean of recall and precision for biological targets.
4. **Effect sign accuracy**: direction agreement among rejected targets.
5. **Execution validity**: proportion of runs with valid, non-empty output.

Primary ranking is lexicographic:

1. execution validity;
2. FDP at or below 0.10 in the primary BH analysis;
3. higher power;
4. higher F1;
5. lower effect-estimate bias.

No method is declared globally best if its ranking changes across scenarios.

## Implementation status

The four primary compositionally-aware methods have passed smoke integration:
ALDEx2, ANCOM-BC2, LinDA and MaAsLin2. The two transparent CLR baselines remain
planned. See `UNIFIED_METHOD_RUNNER.md` and
`outputs/method_smoke/smoke_report.md`.

## Secondary endpoints

- effect-size bias and correlation;
- project-level sign consistency;
- number of discoveries;
- BY sensitivity;
- runtime and memory;
- convergence/failure reasons.

## Reproducibility

- Scenario seeds: `4000–4019`.
- Input counts: one file per scenario and seed.
- All random procedures inside methods receive recorded seeds.
- Failed runs remain in the manifest and denominator.
- Empty or malformed outputs are failures, not missing-at-random exclusions.

## Stop conditions

- More than 20% of a method's smoke tests fail: fix integration before full runs.
- A method cannot respect or approximate the project-blocked assignment: keep only
  as a diagnostic baseline, not in the primary ranking.
- The truth manifest and count file disagree on feature IDs or sample IDs: stop.
- Any post hoc change to the multiple-testing family requires a new benchmark
  version and rerun of every method.
